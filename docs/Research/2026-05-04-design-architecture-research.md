# How templated AI generation systems are built, and the precedents for each CombatDen pattern

Most of the CombatDen pipeline's architectural moves have direct published precedents: the single-document tenant model, the page→flow→tenant cascade with sparse patches, the curated Lottie library plus recoloring, and screenshot-based critique all appear in Shopify themes, WordPress `theme.json`, Material 3, Spelunky, Synthesia, and the Design2Code research line. **Two have no located precedent as named patterns**: the *unified* "wishes ledger" feeding both prompt tuning and library expansion, and the *scope-tiered* (page/flow/app) coherence-review hierarchy. For the application itself — brand brief to fully customized production Flutter app, end to end — **no publicly identifiable competitor was found**, while every adjacent vertical (slides, sites, ads, video, game art) has several. Each claim is substantiated below against named systems and the research literature.

## 1. The landscape: what "templated AI generation" actually looks like across domains

Across roughly 50 systems surveyed in slides, websites, mobile apps, ad creatives, brand identity, video, game art, procgen, and white-label theming, four facts dominate:

**Almost every successful system is curated-library recombination with ML doing slot-filling and ranking, not free-form pixel generation.** Slide tools (Gamma, Beautiful.ai, Tome, Decktopus, Visme, Piktochart, Microsoft Copilot in PowerPoint) all draw from curated layout libraries. Logo "generators" (Looka, Brandmark, LogoAI, Tailor Brands) are explicitly **parametric template recombination at scale** — Looka's own blog frames this as symbol × font × color × layout assembly with ML-driven recommendation; Brandmark goes furthest into actual ML (CNN embeddings of icons, GANs for color schemes, LogoRank quality scoring) but still composes parametrically. Game-asset platforms (Scenario.gg, Layer.ai, Promethean AI) use either fine-tuned LoRAs over a studio's curated dataset or pure semantic retrieval over a curated 3D library. AI video tools (Synthesia, HeyGen, Runway) overlay brand kits onto curated avatar/template libraries. Even Canva's ambitious "Design Model" — closest to genuine generative IR — is constrained to emit *editable layered designs that look like template outputs*. The exceptions that try true generative output (Pencil for ads, Canva's Design Model) compensate with heavy guardrails: brand context conditioning, performance-prediction filtering, bias correction.

**Nearly every system uses a structured intermediate representation, not pixels or final code.** Gamma's atomic unit is the **card** — a structured container with explicit slots (`themeLogo`, header/footer, accent image), exposed via the public Generations API. Beautiful.ai's **Smart Slides** are constraint-based parameterized layout components (~300 of them). Microsoft Copilot in PowerPoint operates on **OOXML + Slide Master + sample slides** — Copilot picks layouts from the user's template's sample slides and fills placeholders by type/position/size. Builder.io's **Mitosis** is the cleanest public example: a static-JSX-derived JSON AST (`MitosisComponent`) compiled to React/Vue/Angular/Svelte/Solid/Qwik/RN/Flutter/SwiftUI/Jetpack Compose. Locofy's recent ArXiv paper introduces "Large Design Models" with explicit Design Optimiser + Tagging + Auto Components stages. Plasmic, Framer, FlutterFlow, Uizard, Power Apps all store designs in proprietary structured models. The pure-code-direct path (v0.dev, Lovable, Bolt.new) is *the minority pattern* and is mostly confined to AI website builders that emit React+Tailwind+shadcn.

**Brand kit is universally a first-class, separate entity.** Synthesia's Brand Kit (logo, palette up to 120 colors, fonts, avatars, media) is workspace-scoped; HeyGen has the same. Canva has Brand Kit plus per-user *Living Memory*. Jasper has a two-part brand voice IR: **Memory** (factual product/audience info from URL crawls, used as RAG grounding) and **Tone & Style** (learned voice descriptor + curated excerpts + style-guide rules). Typeface's **Arc Graph** is a brand graph ingesting DAM/CMS into a queryable representation, with a continuously-running **Brand Agent** that flags off-brand outputs across channels. Auto-extract-brand-from-URL is now table stakes (Synthesia, HeyGen Brand System, Visme Brand Wizard).

**Multi-stage pipelines have replaced one-shot generation in every category that survived past 2023.** Beautiful.ai explicitly markets the shift from one-shot to "creation-as-conversation": theme first → low-fidelity outline → polished slides → per-slide regeneration. Webflow AI has structure → theme (global vars + reusable text styles) → AI Assistant for copy → CMS Collections. Wix ADI does questionnaire → layout → theme → GPT-3.5/4 copy → image generation. v0.dev's "composite model family" is a 4-stage pipeline (RAG-augmented dynamic system prompt → frontier base model → "LLM Suspense" stream manipulation → fine-tuned AutoFix model trained via reinforcement fine-tuning). Builder.io Visual Copilot is three-stage: in-house design model trained on 2M+ design→code pairs → Mitosis compiler → fine-tuned LLM polish. Apple's Athena paper (arXiv:2508.20263, 2025) explicitly motivates multi-stage scaffolding by the failure of single-prompt full-app generation.

## 2. Recurring architectural patterns and where each shows up

**The "curated substrate + parametric assembly + validator" pattern is essentially universal where coherent multi-artifact output is required.** Spelunky's well-documented pipeline (Derek Yu's *Spelunky* book, the published `scrRoomGen`) is a textbook reference: 4×4 grid of room *types* (Side/Drop/Landing/Random) → hand-authored 10×8 templates pulled by type → sub-pattern randomization → solvability validator that retries on failure → entity decoration. Wave Function Collapse formalizes the same idea as a constraint solver. Houdini Digital Assets package node networks behind typed parameter schemas. Promethean AI literally retrieves from a curated 3D asset library — no diffusion at all. Scenario.gg's "your style, scaled" trains LoRAs on the studio's curated dataset. The CombatDen tagged-Lottie-library + brand-recoloring + Pydantic root-validators implementation is the **same shape**.

**The cascade-with-sparse-overrides pattern dominates theming.** Shopify's Online Store 2.0 has the most precise public spec: `settings_schema.json` (developer-authored input schema) → `settings_data.json` (per-merchant values, including a `current` and named `presets`) → JSON `templates/*.json` (page-level wrappers) → per-section `{% schema %}` blocks → per-instance dynamic source bindings. Each layer is a sparse JSON patch over the previous; multi-store white-labeling is implemented by switching presets. WordPress block themes have a documented four-layer cascade (core defaults → block defaults → `theme.json` → user overrides in DB). Material Design 3 has the canonical three-tier *token* cascade: **reference** (`md.ref.palette.primary40`) → **system** (`md.sys.color.primary`) → **component** (`md.comp.fab.container.color`); Material You re-themes the entire UI by swapping just the reference layer. Salesforce Lightning Design System 2 (2025) replaced raw tokens with **global styling hooks** (`--slds-g-spacing-4`) so per-org theming flows through CSS custom properties. Plasmic exposes the most expressive sparse-override system: variants × slots × responsive tokens × per-instance overrides.

**Two-tier vs three-tier token systems are now the standard split.** shadcn (consumed by v0.dev), Polaris, and Spectrum use two tiers (palette/primitive → role/alias). Material 3 and SLDS use three (primitive → semantic → component). The **three-tier model is dominant in mobile/Flutter** because Material 3 is the de-facto baseline.

**Self-critique loops have moved from research to production but remain shallow.** Decktopus enterprise has an explicit automated brand-compliance check (logo placement, color accuracy, style) that *regenerates failing slides*. AdCreative.ai's Creative Scoring CNN — a separate model trained on ad performance data — predicts CTR for every variant and surfaces the top performers; this functions as a learned critic. Pencil applies the same pattern with a model trained on $1B+ of media spend. Brandmark has a LogoRank model. Typeface's Brand Agent runs continuously across channels. Jasper measures acceptance rate, edit rate, and thumbs feedback as model-quality telemetry. v0.dev's reliability work is sophisticated but *not* visual: it operates on token streams and runtime/build errors via the AutoFix model trained via reinforcement fine-tuning on Fireworks. **Despite popular belief, no commercial system was found to take screenshots of its own rendered output and have a VLM critique them as a documented pipeline stage** — the pattern exists in research (Design2Code's Self-Revision Prompting, Critic-V, Sketch2Code, ScreenCoder, DesignCoder) but not yet in named commercial products at the level the user is proposing.

**Hierarchical decomposition with intermediate representations is the only approach that actually scales to apps.** Apple's Athena (arXiv:2508.20263, 2025) is the closest published precedent for the user's pipeline: chat-based scaffolding through three IRs — **storyboard** (navigation), **data model**, **GUI skeletons** — culminating in code. DesignCoder (Chen et al., 2025) decomposes screens into components, generates per-component, repairs via VLM critique. ScreenCoder uses a three-stage grounding → planning → generation modular pipeline. MetaGPT (Hong et al., ICLR 2024) and ChatDev (Qian et al., ACL 2024) decompose by *role* (PM/architect/engineer/QA) but enforce **structured outputs between agents** rather than free-form chat — explicitly to prevent failure modes.

## 3. Where this kind of architecture is usually applied

The strongest concentration is in **content-template categories where the artifact has an obvious "frame + slots" shape**: presentations, websites, marketing pages, ad creatives, video templates, logos, infographics, social-media kits. These succeed because the output schema is well-bounded and curated component libraries already exist (PowerPoint masters, Figma kits, Webflow blocks, Synthesia templates).

A second cluster is **white-label SaaS theming**: Shopify's storefront preset system, Salesforce SLDS Themes & Branding, Atlassian per-site theming, Power Apps environment theming — all classic per-tenant cascade with sparse overlays.

A third cluster is **game art and procgen**: Scenario, Layer.ai, Promethean for studio-curated asset generation; Spelunky/No Man's Sky/Caves of Qud for procedural worlds; Houdini HDAs for parametric assets. The architectural lessons (curated tilesets, constraint validators, semantic typing, parameter envelopes) are directly applicable to design generation but the *fields don't talk to each other much* — game procgen literature is rarely cited in UI generation work, which is a missed opportunity.

The pattern is **uncommon-to-rare in three places**: (a) full mobile app generation from a brand brief — FlutterFlow, DreamFlow, Rork, Bubble, Adalo all generate apps from *functional* descriptions and treat brand customization as post-hoc; (b) document/report generation beyond slides — most "AI report" tools are still single-document chat outputs with templates rather than schema-driven multi-stage pipelines; (c) personalized education/learning content with brand consistency — adjacent to the user's territory but underdeveloped.

**No publicly identifiable competitor produces a fully-themed, brand-customized, production-ready mobile app from a brand brief end-to-end.** The closest analogues fragment across the stack: Synthesia/HeyGen prove brand-kit-over-templates at scale (but for video); FlutterFlow's MCP-based agentic CLI proves prompt-to-Flutter pipelines (but treats brand as theme settings, not a brief); Webflow + Relume prove brand-theme cascades for sites (but not mobile apps). The CombatDen positioning at the intersection appears defensible.

## 4. Pattern-by-pattern precedents for the CombatDen architecture

### The single-Pydantic-document tenant model with shape-only schema and validators
**Precedent: standard.** Pydantic + the Instructor library's "try-reject-repeat" loop (Liu et al.) is the canonical Python-side pattern for structured LLM outputs and is widely deployed. The "single per-tenant document" is the same idea as Shopify's `settings_data.json` (one merchant blob containing presets and overrides) and WordPress's user-layer Site Editor settings. **The interesting framing** is that "shape-only schema" — required slot structure but value-permissive — maps tightly onto **program sketching** (Solar-Lezama, UC Berkeley 2008), where a sketch declares holes that an inductive synthesizer fills against a specification. The schema-as-sketch framing is theoretically rigorous but empirically *underexploited* in the LLM literature, which mostly treats structured generation as JSON-mode plumbing. The use of root validators for *cross-field invariants* (every shared-image placeholder resolves) is a known gap that constrained-decoding frameworks (Outlines, Guidance, XGrammar) cannot address — they enforce only local schema validity. The approach is consistent with current practice in production LLM apps.

### The page→flow→tenant cascade with sparse patches
**Direct match to multiple well-known engineering patterns.** Functionally equivalent to: CSS specificity cascade; Shopify's preset → current → template → section override chain; WordPress's core-defaults → block-defaults → theme.json → user-overrides four-layer cascade; Material 3's reference → system → component token tiers (inverted in direction); Plasmic's variants × slots × responsive tokens. JSON Merge Patch (RFC 7396) describes the exact merge semantics. The "first non-None wins" walk is what Shopify and WordPress do at runtime. **Adding "flow" as a middle tier between page and tenant is somewhat distinctive** — Shopify and WordPress have only two layers below the theme, Material 3 has component-level which is finer than "flow." The closest analog is Webflow's "section" tier between site and component, or shadcn's CSS-variable scoping at section level. The stated motivation (lock motion timing, card radius, spacing once per related-screen group) matches Beautiful.ai's "Smart Slide design logic", which places some decisions at a sub-deck scope. **Precedent: the cascade is standard; the explicit middle "flow" tier is an extension with only partial precedent.**

### Separating non-runtime "intent" metadata from runtime-readable schema
**Common in spirit, slightly unusual in execution.** Most systems separate brand-kit-as-data from rendered-artifact (Synthesia, HeyGen, Plasmic, FlutterFlow, Material 3 token files, Webflow design-system layer). What's distinctive is the **explicit pipeline boundary** — direction metadata travels with prompts but the runtime *literally cannot read it*. Most systems either store everything together and just choose which keys the renderer consumes (FlutterFlow's BrandKit, Synthesia's Brand Kit), or keep brand voice as a system-prompt conditioner that's also stored on the brand object (Jasper Memory). The CombatDen approach builds the prompt-time vs runtime-time distinction into the *type system*, so direction cannot leak into rendering. The closest analogs are Jasper's Memory (RAG grounding only, never rendered) and Plasmic's separation between Studio metadata and codegen output. **Precedent: the separation principle is standard; enforcing it in the type system is more restrictive than the surveyed norm.**

### Multi-tier coherence review (page → flow → app) with screenshot-based app-level critique
**Precedent: the ingredients are canonical; the scope-tiering is uncommon.** The individual ingredients:
- Iterative critique loops: Self-Refine (Madaan et al., NeurIPS 2023), Reflexion (Shinn et al., NeurIPS 2023), Constitutional AI (Bai et al., 2022).
- Screenshot/VLM-based UI critique: Design2Code (Si et al., NAACL 2025) explicitly validates "Self-Revision Prompting" where the model views its rendered output and critiques it; Critic-V uses TextGrad-optimized critique prompts; Sketch2Code does multi-turn refinement; Vision-Guided Iterative Refinement formalizes the loop.
- Confidence-based gating: implicit in many systems; the literature on Quality Ceiling Effect (Duan et al., arXiv:2403.13139; GameUIAgent) explicitly recommends confidence-thresholding because **VLM critique degrades on already-good designs** (Pearson r = -0.96 between initial quality and self-correction gain in GameUIAgent).

The **scope-tiered hierarchy** (component-level → flow-level → app-level, increasing in scope and granularity) is **less common in published architectures**. MetaGPT's PRD→architect→engineer chain and ChatDev's seven-role ChatChain decompose by *role*; Reflexion stages decompose by *episode*; Athena uses *artifact-type* tiers (storyboard/data/GUI). Decktopus's automated brand check is a single-tier industrial analog. Typeface's Brand Agent runs as one continuous validator. **Explicit nested *coherence-scope* tiers do not appear to be a named pattern in published work**, though the underlying intuition (review wider scopes only after narrower ones converge) is consistent with hierarchical reflection in Park et al.'s Generative Agents (UIST 2023) and with the locality principle in JSON Whisperer (arXiv:2510.04717). 

**Documented failure modes for this stage**: (a) LLM-as-judge has measured self-enhancement bias (Zheng et al. MT-Bench); (b) the Quality Ceiling Effect means an app-level review can *worsen* already-good output absent confidence gating, and the gating threshold is not derivable from the published work; (c) the GameUIAgent "Rendering-Evaluation Fidelity Principle" finds that mismatched rendering fidelity inverts the VLM reward signal, making screenshot-generation fidelity at the app-review stage load-bearing.

### The "wishes" self-improvement DB pattern
**Precedent: every ingredient has one; the composition does not.** The ingredients:
- Voyager (Wang et al., TMLR 2023) grows an ever-expanding **skill library** of executable code — but from *successes*, not from frustrated intentions.
- Reflexion's verbal episodic memory stores **failure reflections** across trials — but feeds reasoning, not library/prompt expansion.
- DSPy (Khattab et al., arXiv:2310.03714) bootstraps few-shot prompts from **execution traces** via BootstrapFewShot/MIPROv2 — but the traces are successful runs, not "things I wanted but couldn't do."
- Park et al.'s Generative Agents (UIST 2023) build hierarchical reflection trees over a memory stream — relevant for the structure but not for the dual downstream consumption.
- Tandon et al. (2022) "Learning to Repair: Repairing model output errors after deployment using a dynamic memory of feedback" is the closest spirit — a deployed feedback memory.

The **specific composition** — every LLM module emitting a structured "things I wanted to do but couldn't / rules I bent" record that simultaneously feeds (a) prompt tuning and (b) library/component vocabulary expansion — is **not, as far as the published literature shows, a named or consolidated pattern**. Voyager grows from successes; Reflexion stores failures but doesn't expand a library; DSPy optimizes prompts but doesn't grow vocabularies. The CombatDen "wishes ledger" is essentially a fusion of Voyager (library expansion) + Reflexion (verbal failure memory) + DSPy (trace-driven prompt tuning), with the inversion that **library growth is driven by frustrated wishes rather than successful skills**. Mechanically, a wish encodes a "nearby capability that the current library/prompt could not satisfy" — the same signal class a curriculum-learning system consumes. No published work was found consolidating these three into one ledger.

### Batched icon generation for set coherence
**Precedent: the tactic is standard; the prevailing industry approach is curation rather than batched generation.** Batched generation with shared seed/style reference is well-established in image gen — Scenario.gg LoRAs, Ideogram Character, IP-Adapter/ControlNet pipelines all use it. But **the dominant industry approach for icon set coherence is curated icon libraries with consistent stroke weight/style**, not batched generation. Visme, Piktochart, Beautiful.ai, Decktopus, Looka, Tailor Brands, LogoAI, every major slide tool, and every major site builder use curated icon libraries. Brandmark is the unusual case: it embeds icons in a CNN-derived feature space and matches them by similarity, which gets style-family coherence without explicit tag curation. The CombatDen approach (batching the whole icon set in one shot to share stroke weight, detail, corner geometry) runs against the surveyed industry practice: most of the field moved off per-tenant icon generation because of output variance and adopted curation. CombatDen also carries the Lottie-library-with-brand-recoloring path (below), so both approaches are present in the same pipeline.

### Flow-level shared decisions as a distinct pipeline stage
**Precedent: partial.** Most systems have two scopes (theme/component) or no explicit middle scope at all. Beautiful.ai's Smart Slides bake "design logic" at the slide-component level but not at a "section of the deck" level. Webflow's section components inherit from global vars but don't represent a formal middle scope. Athena (Apple, 2025) has a *storyboard* artifact representing app navigation, but it's an artifact tier, not a *decision-locking* tier. The closest spirit is Material 3's *system* token tier — semantic decisions locked between primitives and components. The CombatDen "flow" tier formalizes the case where a design decision (motion timing, card radius cascade) varies neither screen-by-screen nor globally. The underlying distinction is standard design practice but was **rarely found surfaced as an explicit pipeline stage with locked outputs**. Its cost is one more cascade level and one more critic tier. The novelty is in the framing, not the mechanism.

### Curated tagged Lottie + brand recoloring + named-preset fallback
**Precedent: canonical for this category.** The pattern — curated tagged asset library + parametric customization + deterministic fallback — has the strongest convergent precedents in the entire architecture:
- Spelunky's hand-authored room templates with type tags + procedural assembly + fallback retries.
- Wave Function Collapse: tagged tileset + adjacency constraints + backtrack-on-contradiction.
- Promethean AI: 100% curated 3D library with semantic tags + spatial reasoning composition.
- Scenario.gg, Layer.ai: studio's curated training set + LoRA fine-tune + reference controls.
- Synthesia/HeyGen: curated avatar+template library + brand-kit overlay + scene-level overrides.
- Looka, Tailor Brands, LogoAI: curated symbol×font×color libraries + ML-driven recommendation.
- Houdini HDAs: curated parametric assets with versioned exposed-parameter schemas.
- LottieFiles' own ecosystem already supports color customization at runtime.

The named-preset fallback is the WFC-style "if the constrained generation fails, drop to a known-good tile" pattern. Three further mechanisms appear in the precedent systems but not in the CombatDen pipeline: (a) explicit semantic typing of asset tags (Spelunky's room types, Promethean's spatial categories), constraining selection to compatible assets per slot; (b) versioned exposed-parameter schemas per asset (Houdini HDA pattern), where each animation declares its recolor targets, timing knobs and slot constraints; (c) post-assembly validators (Spelunky's solvability check) run before commit.

## 5. Mapping to the academic literature

| CombatDen element | Closest research analogue(s) | Novelty |
|---|---|---|
| Pydantic shape-only schema + root validators | Solar-Lezama program sketching (2008); Instructor try-reject-repeat | Engineering-standard; sketch framing underused |
| Page→flow→tenant cascade | Shopify presets; WordPress `theme.json`; Material 3 token tiers; JSON Merge Patch (RFC 7396) | Standard cascade |
| Direction metadata separated from runtime | Jasper Memory (RAG-only); Plasmic Studio metadata; DTCG token files | Standard separation, more rigorously enforced |
| Multi-tier coherence review | Self-Refine (Madaan); Reflexion (Shinn); MetaGPT SOPs; ChatDev ChatChain | Hierarchical *scope-tiered* framing is uncommon |
| Screenshot-based app-level critique | Design2Code Self-Revision (Si et al., NAACL 2025); Critic-V; Sketch2Code; Vision-Guided Iterative Refinement | Canonical research recipe; not yet productized |
| "Wishes" feeding prompt tuning | DSPy bootstrap (Khattab); Reflexion verbal memory | Direct precedent for trace→prompt |
| "Wishes" feeding library expansion | Voyager skill library (Wang et al., TMLR 2023) | Voyager grows from successes; CombatDen inverts to grow from frustrations |
| Unified wishes ledger feeding both | **No published precedent** | Genuinely novel composition |
| Sparse typed overlays generated by LLMs | JSON Whisperer (arXiv:2510.04717, October 2025) | Concurrent academic work; CombatDen's typed variant is a contribution-shaped niche |
| Curated Lottie + parametric assembly | Spelunky room templates; WFC; Promethean AI; Scenario LoRAs; Houdini HDA | Architecturally canonical |
| Hierarchical app→screen→component generation | **Athena (Apple, 2025, arXiv:2508.20263)**; DesignCoder; ScreenCoder | Athena is the closest single-paper analogue; lacks the wishes/critic-tier pieces |

**Three cautions from the literature worth pricing in:**
- **Self-enhancement bias in LLM-as-judge** (Zheng et al., MT-Bench 2023): a model judging its own output is biased toward it. Use cross-model judges or rubric-anchored judging (G-Eval, Prometheus) at the coherence-review stages.
- **Quality Ceiling Effect** (Duan et al., arXiv:2403.13139; GameUIAgent): VLM critique degrades on good designs and can *worsen* output. The confidence-gating in CombatDen's review tiers addresses this but threshold tuning is non-trivial.
- **Multi-agent debate gains may be overstated** (Smit et al., arXiv:2502.08788, "Stop Overvaluing Multi-Agent Debate"): if any of the review tiers grow into ensemble debate, measure rigorously.
